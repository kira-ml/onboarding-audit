# Research Brief — Onboarding Audit

**For:** a fintech data science / ML research reviewer.
**Length:** 2 pages.
**Status:** v1.0.0 pilot; results from the pre-registered pilot, the propensity
sensitivity, and the covariate sensitivity.

---

## 1. The decision

A bank or e-wallet must decide whether to approve, review, or reject each new
account application. The onboarding policy is one of the highest-leverage
controls in the institution: it determines who enters the financial system,
which fraudulent applications are stopped, which legitimate applicants are
excluded, and how much manual review capacity is consumed.

The practical question:

> *If we deploy this new onboarding policy, will it catch more fraud without
> rejecting more good customers — and can we defend the expected-impact number
> to a risk committee, an internal auditor, and the regulator?*

## 2. Why the number is hard to trust

The data needed to answer the question is generated by the current policy.

- **Selection.** Reviewed applications get a fast, reliable label. Approved
  accounts are labeled only if fraud is detected later. Rejected applicants have
  no outcome.
- **Delay.** Review labels arrive in days; post-approval fraud labels arrive in
  weeks or months; some labels are censored at the cutoff.
- **Capacity.** Only a small fraction of applications can be reviewed; the
  review policy is part of the decision.
- **Audit.** A random post-hoc verification of approved applications can recover
  unbiased labels for the approved margin. A random approval of would-be-rejected
  applicants would deliberately onboard fraud; a random rejection would exclude
  legitimate customers.

A naive evaluation on the labeled subset answers a different question from the
one the business is asking.

## 3. Why now (Philippines)

- **BSP Circular 1170 (2023)** governs eKYC and digital identity proofing.
- **BSP Circular 1213 (2025)** requires continuous calibration, stress testing,
  and independent review/audit of the FMS — but its 11 mandated log fields
  contain no decision, score, or outcome.
- **AFASA s.6** ties inadequate controls to restitution; conviction is not a
  prerequisite.
- **BSP Project Sapiens (2024)** names **sampling bias** and **labelling bias**,
  finds only 6/10 deep-dive institutions validate models during development and
  ongoing, and notes some banks limit AI audit to credit/lending.
- **Fraudulent onboarding is the entry point** for mule accounts and scams:
  identity theft/ATO/social engineering are 76% of reported cyber-fraud losses;
  AMLC recorded 821,279 mule-related STRs worth PHP 510B; GCash blocked 4M
  accounts in 2023.

## 4. What this project does

- **Primary estimand:** policy value on the logging non-rejected population
  (`P0`), the part logs can identify.
- **Reject margin:** full-population bounds, not a point estimate.
- **Estimators:** naive, IPW, doubly robust, audit-only, bounds.
- **Propensities:** oracle, action-level estimated, noisy, and per-action
  covariate models.
- **Benchmark:** BAF account-opening applications with known ground truth.
- **Stress tests:** audit size, review capacity, delay, outcome-dependent
  labels, false-reject cost.
- **Negative controls:** full observation, full audit, permutation, capacity,
  no leakage.
- **Artifact:** schema, validator, audit design, memo, benchmark, paper.

## 5. Pilot result

| Result | Number |
|---|---|
| Naive relative bias (four policies) | **+111.6% to +278.5%** |
| Observation-rate sweep: naive bias / DR max bias (known `e`) | **7.8–538.5% / 1.89%** |
| Naive rank inversions / P(select true best) | **1.00 / 0%** |
| True P0 ranking | `better_model < incumbent < lenient_cost < strict_cost` |
| Naive ranking | `incumbent < better_model < lenient_cost < strict_cost` |
| DR max \|relative bias\| / mean coverage | **0.94% / 96.0%** |
| IPW max \|relative bias\| / mean coverage | **1.18% / 94.5%** |
| Audit-only at 1%: max bias / coverage / ESS | **2.98% / 84.5% / 1,271** |
| Audit-only at 2%: max bias / coverage / ESS | **1.82% / 86.5% / 2,546** |
| DR RMSE, 0% → 2% audit | **0.001159 → 0.001068** |
| Reject-margin bounds: main interval | **0.009942** (`frej_002`: **0.203**) |
| Incumbent bounds coverage of true full value | **34%** (not a CI) |
| Outcome-dependent: audit-only bias | **-2.37% to -1.98%** |
| Outcome-dependent: IPW / DR bias | **+43.9% to +368.3% / +596.4% to +1301.5%** |
| Estimated `e`: DR max bias / coverage | **1.43% / 93.5%** |
| Estimated `e`: IPW max bias / coverage | **2.92% / 92.0%** |
| Noisy `e` (sigma 0.25): DR / IPW | **1.58% / 96.5%** vs **7.01% / 93.0%** |
| Double robustness: DR wrong outcome / wrong `e` | **+0.14% / +0.36%**; IPW −36.7%, plug-in +5.1% |
| Outcome-dependent + estimated `e`: audit-only | **2.58% / 82.5%**; IPW/DR fail |
| Covariate observation: action IPW / DR | **67.52% / 21.25%** |
| Covariate observation: model IPW / DR | **1.97% / 2.48%** |
| Covariate + 45-day delay: action / model | **64.27% / 20.27%** vs **3.35% / 3.68%** |
| Covariate coverage (oracle / model) | **89–90% / 89.5–91.5%** (heavy tails) |

**Interpretation:** the naive evaluation is not a small approximation; it
overstates cost and would reject the better policy. DR recovers the identified
value and the true ranking, and both DR and IPW survive estimated action-level
propensities; DR is better under noise. Under covariate-dependent observation,
action-level IPW fails and
the fitted covariate model is the correction; DR is more robust than IPW but
heavy weights can undercover the interval. The reject margin still requires
bounds or a controlled approval design. The audit is a validation and
outcome-dependent-label tool, not a universal bias fix. When `e` is noisy, prefer
DR; when observation depends on application features, use
the covariate propensity model and report the weight diagnostics.

## 6. What a team can use

1. **A decision-log schema** that keeps BSP 1213's 11 fields and adds the
   decision/observation/label fields needed for evaluation.
2. **A validator** that says which estimators the log can support.
3. **An audit design** that is legally defensible: post-hoc verification and
   shadow scoring, not random approvals/rejections.
4. **An audit-ready memo** that separates measured, assumed, and unverifiable
   claims.
5. **Action-level and covariate propensity models** with weight/ESS diagnostics.
6. **A public benchmark** and reproducible pilot.

## 7. What it is not

- Not a fraud detector or a new classifier.
- Not a production system or a claim about a specific bank.
- Not a causal deployment effect.
- Not a point estimate for the unobserved reject margin.
- Not a substitute for legal, compliance, or model-risk review.

## 9. Why this is a research contribution

- It formalizes the account-opening policy-evaluation problem with
  policy-induced selection, delayed/censored labels, capacity, and a legal log
  schema.
- It distinguishes what is identified from what is not, and reports bounds
  rather than false precision.
- It tests the estimators against known ground truth with negative controls.
- It shows when an audit helps and when it does not.
- It ships the measurement layer, not just a result.
